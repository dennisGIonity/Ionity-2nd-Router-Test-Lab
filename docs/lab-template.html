Rules

  • Nothing lab-related on the household network: no boards, no lab DNS, no GateFlame.
  • The laptop cable goes into an H3C LAN port. Never the WAN port.
  • Band split: the household owns 2.4 GHz (TP-Link), the lab lives on 5 GHz (IONITY-LAB, ch 149).
  • Exception: ESP32-S3 and Pico 2 W radios are 2.4 GHz only. They get one low-power lab network, IONITY-LAB-IOT on ch 11, which never overlaps the household's ch 1. Dual-band ESP32-C5 boards join the 5 GHz network.
  • WiFi passwords are typed into SET-LAB-WIFI.cmd only, never in chat or commits.

Set up a lab

  1. Laptop cable → an H3C LAN port.you
  2. H3C admin http://192.168.124.1: 5 GHz SSID IONITY-LAB ch 149. 2.4 GHz SSID IONITY-LAB-IOT ch 11, 20 MHz, low power, with band steering off so the two stay separate. Reserve 192.168.124.4 for MAC 40:C2:BA:F5:B9:5F.you
  3. TP-Link http://192.168.0.1: 2.4 GHz ch 1, 20 MHz, power High. 5 GHz ch 36.you
  4. Double-click SETUP-LAB-NETWORK.cmd and approve the admin prompt.you
  5. Double-click SET-LAB-WIFI.cmd, accept IONITY-LAB-IOT and type its password (hidden).you
  6. Start the lab: START-LAB.cmd (the first run on a new PC also needs lab.ps1 setup).Claude
  7. Flash each board with its project's flasher (ESP32-MCP: scripts\add_device.ps1 -Port COMx).Claude
  8. Health check, every line OK: LAB-STATUS.cmdClaude

Add a project to the lab

The lab is its own project, Ionity-Lab (E:\.IONITY-LAB). A new hardware project doesn't copy it; it registers in lab.json → projects with its path, firmware folder, env keys, start script and health URL. SET-LAB-WIFI.cmd, START-LAB.cmd and LAB-STATUS.cmd then cover it automatically. Run the health check before every client demo.
